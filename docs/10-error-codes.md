# ShipFlow API 错误码

错误码格式：`模块-四位数字`。HTTP 状态码表达协议层结果，错误码表达业务原因。

## 与 OpenAPI 的对应关系

`openapi/shipflow-api.yaml` 使用统一响应组件：`AuthError` 对应 401、`Forbidden` 对应 403、`NotFound` 对应 404、`Conflict` 对应 409，业务规则组件对应 422，`BadRequest` 对应 400。响应体中的 `error.code` 必须使用本文件中的错误码，响应头 `X-Trace-Id` 必须与响应体 `traceId` 一致。

核心接口必须覆盖 401、403；资源型接口必须覆盖 404；幂等、乐观锁和状态冲突必须覆盖 409；参数和业务规则校验必须覆盖 400 或 422。重复轨迹事件只通过 `TrackingEventResult.status=DUPLICATE` 表示成功，不重复推进状态或写入业务影响。

## COMMON

| 错误码 | HTTP | 含义 |
|---|---:|---|
| `COMMON-1001` | 400 | 请求参数错误 |
| `COMMON-1002` | 401 | 未登录或 Token 无效 |
| `COMMON-1003` | 401 | Token 已过期 |
| `COMMON-1004` | 403 | 权限不足 |
| `COMMON-1005` | 409 | 乐观锁冲突 |
| `COMMON-1006` | 404 | 资源不存在 |
| `COMMON-1007` | 500 | 内部系统错误 |
| `COMMON-1008` | 400 | 请求体格式错误 |
| `COMMON-1009` | 409 | 幂等键与请求内容冲突 |
| `COMMON-1010` | 409 | 相同幂等请求正在处理中 |

## AUTH

| 错误码 | HTTP | 含义 |
