# 正式报价转订单学习笔记

## 业务流程

租户商户在正式报价详情中先校验报价可用性。只有仍有效且未被消费的报价，才可补充发件地址、收件地址和至少一项货物明细，创建一张初始状态为 `DRAFT` 的物流订单。

## 参与方与状态

- 租户商户：拥有 `quote:read` 可查看报价；拥有 `order:create` 才能创建订单。
- 前端：收集订单创建契约要求的资料，锁定收件国家/地区为报价目的国家/地区，并防止重复点击。
- 后端：以当前 JWT 的 `tenant_id` 隔离数据，在事务中创建订单、地址、包裹、货物和报价快照。
- 报价：从可消费状态变为已使用，不能重复创建订单。
- 订单：创建后进入 `DRAFT`，后续由订单提交、仓库和轨迹模块继续处理。

## 业务规则与异常路径

- 报价过期、取消或已使用时，不允许创建订单。
- 收件国家/地区必须和报价目的国家/地区一致。
- 地址和每项货物的必填字段由后端再次校验；前端提示不替代服务端校验。
- 创建请求使用 `Idempotency-Key`；同一幂等键的重复请求应返回同一订单，避免重复写入。
- 前端不保存或计算报价金额、计费重量、渠道和规则快照，它们由后端从不可变报价复制。

## 后续问题

当前报价创建时不收集收发件地址和货物明细，因此报价转订单需要人工补充这些资料。若业务希望减少重复录入，需要先定义店铺默认发件地址、地址簿及商品目录的租户隔离、授权和审计规则。
