# 店铺维护幂等与停用下单学习笔记

## 结论

店铺编辑和启停属于同一租户内的资源写操作，必须先通过 `tenant_id + user_id + role + active sys_user_store_scope` 资源归属校验，再处理幂等记录和版本更新。这样既不会通过错误响应泄露未授权店铺存在性，也不会让幂等键绕过权限边界。

## 实施要点

- 编辑和启停均使用 `Idempotency-Key` 与请求内容摘要；同键不同请求体返回 409，同键同请求重放原资源结果。
- `merchant_store.version` 作为条件更新版本，过期版本返回并发冲突；事务内写入已有审计日志。
- 订单创建前复核报价所属店铺仍为 `ACTIVE`，停用店铺不能创建新订单，历史订单查询不受影响。
- 前端维护按钮仅对 `store:manage` 可见，启停需要二次确认，平台账号不回显；时间仍按 UTC 存储、Asia/Shanghai 展示。
