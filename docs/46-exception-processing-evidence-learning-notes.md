# 异常处理、证据附件与索赔关联学习笔记

## 本次闭环

- 异常资源先通过订单的 `store_id` 与 `StoreScopeMapper` 校验租户、角色和店铺授权，再读取或写入异常、处理记录、证据和索赔。
- `responsible_party` 直接存储在 `exception_case`，处理记录采用追加模型，避免从审计 JSON 反推业务责任方或丢失处理历史。
- 证据附件以内容 SHA-256 去重，保存文件元数据和内容本体；文件名只用于展示，下载前再次执行异常资源授权校验。
- `claim_record.exception_case_id` 继续作为索赔关联，避免重复建设第二条异常-索赔关系。
- 新增状态支持物流商反馈等待和财务确认等待，状态推进使用白名单和乐观版本条件；所有新时间列按 UTC 存储，接口返回 UTC。

## 验证与边界

- 异常模块定向后端测试覆盖状态机、服务层、Controller、Mapper XML 和迁移静态契约。
- 附件数据库迁移只写入工作区，未执行迁移、生产数据库写入或生产物流调用。
- 附件当前使用数据库 `LONGBLOB` 作为最小可下载存储；后续接入对象存储时需保持内容哈希、租户/店铺授权、幂等和下载审计契约不变。
