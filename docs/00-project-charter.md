# ShipFlow 项目章程

## 项目背景

跨境物流履约涉及订单、仓储、承运商、运输节点、清关、异常处理和费用结算等多个环节。ShipFlow 用企业级仿真方式还原这些业务协作关系，作为测试开发工程师求职项目，展示业务理解、系统设计、接口测试、数据库验证和异步流程测试能力。

## 目标用户

- 需要向日本、美国和欧洲发货的中国跨境商家
- 负责订单履约、仓储、物流和费用结算的商家人员
- 测试开发工程师和质量工程师
- 需要查看履约状态、费用结果和审计记录的管理人员

## 需要解决的问题

- 统一管理跨境物流履约过程中的订单和状态流转
- 处理多参与方协作中的状态同步、重复请求和异常场景
- 依据业务规则计算、核对并结算物流费用
- 让关键业务结果能够通过接口和数据库进行验证
- 沉淀可复现的测试、缺陷和学习记录

## 项目范围

第一版聚焦中国跨境商家向日本、美国和欧洲发货的履约与费用结算流程，包含以下业务模块：

- 租户与用户
- 物流商与物流渠道
- 运费报价
- 物流订单
- 仓库入库与复称
- 仓库出库
- 物流轨迹回调
- 账单导入
- 费用对账
- 异常件与索赔
- 审计日志

项目仍保留多租户业务基础与权限边界、承运商/仓储/外部系统 Mock 协作、异步任务处理、API 自动化测试、数据库断言、测试数据管理、部署配置、项目文档、学习笔记和缺陷报告等支撑范围。

## 暂不实现的功能

- 真实海关系统
- 真实支付宝、微信或其他支付
- 真实物流商账号和生产接口
- 真实汇率接口
- 完整前端页面
- 微服务拆分
- Kubernetes
- 复杂财务发票和税务申报
- 真实客户数据接入
- 真实地图导航、实时轨迹采集和硬件设备接入
- 面向公网的商业化运营与高可用生产部署
- 生产级计费合规、税务申报和财务总账替代

## 技术目标

- 建立清晰的领域边界、状态机和可审计业务数据
- 在业务写操作中落实幂等、事务和重复请求处理
- 统一金额精度、时区、多租户和错误码约定
- 通过 Mock 服务模拟外部依赖及异常响应
- 形成可重复执行、可定位问题的自动化测试体系

## 测试目标

- 覆盖核心履约与结算流程的正常、异常、边界和重复请求场景
- 核心接口同时验证响应结果与数据库持久化结果
- 对异步流程使用轮询验证最终状态和超时行为
- 验证跨租户数据隔离、权限边界和关键业务约束
- 产出真实可追溯的测试结果、缺陷记录和学习笔记

## 最终交付物

- 可运行的履约与费用结算仿真系统
- 外部依赖 Mock 服务
- API 自动化测试及测试数据
- 部署配置和运行说明
- 项目章程、业务流程文档、学习笔记和缺陷报告
- 能够展示业务分析、实现、测试验证和问题定位能力的项目成果
