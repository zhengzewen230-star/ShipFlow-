# 报价查询子模块学习笔记

## 业务流程与参与方

- 当前租户用户从 JWT 的 `tenant_id` 进入报价列表、详情和有效性校验；请求不能指定或覆盖租户。
- 列表按店铺、渠道、状态分页查询；详情返回创建报价时冻结的金额、计费重量、规则版本和费用明细。
- 有效性校验是只读操作，不修改报价状态：依次检查 UTC 有效期、`CANCELLED` 状态以及该报价是否已有物流订单。

## 状态、规则与异常路径

- 查询本身不产生状态变化；正式报价仍保持不可修改。
- `valid_to` 以 UTC 比较，等于当前时刻即视为过期。
- `VALID` 且未过期、未取消、未被订单使用时才可创建订单。
- 报价不存在或属于其他租户统一返回 `404 / COMMON-1006`，避免资源枚举。
- 非租户作用域返回 `403 / COMMON-1004`；非法分页或状态过滤返回 `400 / COMMON-1001`。
- 校验原因固定为 `AVAILABLE`、`EXPIRED`、`CANCELLED`、`ALREADY_USED`，供后续订单创建接口复用。

## 后续问题

- 业务：是否需要把报价目的国家从 `fee_detail` JSON 提升为 `quote` 的独立快照字段，以便强约束和索引查询？
- 技术：后续创建订单时是否直接复用本模块的资格判断，并在同一事务中通过唯一约束再次防止并发重复使用报价？

## 创建与运费计算实现

- 创建报价仅接受当前租户的启用店铺；渠道必须启用、支持目的国家，并存在当前 UTC 时间有效的 `PUBLISHED` 价格规则。
- 体积重量为长×宽×高÷体积系数；计费重量取申报重量和体积重量的较大者，再按规则的进位模式与增量处理，并选择左闭右开的价格阶梯。
- 金额、币种、计费输入、规则版本和 `fee_detail` 在创建时冻结；报价有效期固定为创建时间后 30 分钟（UTC）。
- `fee_detail` 同时保存目的国家、重量计算、进位规则、阶梯号和金额依据，后续订单必须原样复制到 `shipment_quote_snapshot`。
- 创建使用 `api_idempotency_record` 的租户作用域唯一键。同一键且同一请求回放首次报价；同键不同请求返回 `COMMON-1009`；处理中请求返回 `COMMON-1010`。
