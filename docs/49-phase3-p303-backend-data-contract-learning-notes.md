# P3-03 后端统一数据契约学习笔记

更新时间：2026-08-17（Asia/Shanghai）

## 本次完成

- 用单一 `GET /operations/workbench` 快照承载指标、待办、最近订单、风险、时间窗口和刷新时间。
- 由服务端先按 Asia/Shanghai 生成自然日窗口，再转换成 UTC `LocalDateTime` 传给 Mapper；固定 `Clock` 使 24 小时阈值和测试可重复。
- 通过 `merchant_store`、`sys_user`、角色关系和 `sys_user_store_scope` 在 SQL 中重新校验租户、店铺、角色和资源归属；`storeId` 只能缩小范围。
- 复用现有费用调整、账单、对账、异常、轨迹、provider order 和清关资料表，不新增迁移。
- “待财务处理”保留聚合值并固定拆分四项；报价即将过期和订单长时间未处理先使用 24 小时平台默认值。

## 关键经验

1. 现有 `target` 目录中的资源文件可能被其他 Java 进程占用，测试应使用独立构建目录而不是删除或覆盖用户构建产物。
2. 查询参数若直接使用 Spring 数值绑定，格式错误可能先于业务异常映射；本接口先按字符串解析，再统一返回 `COMMON-1001`。
3. MyBatis 动态排序只能使用服务端白名单和 XML `<choose>`，不能把前端 `sortBy` 直接拼接到 SQL。
4. 面单状态必须按 `LABEL_READY` 判断；左连接 provider order 可覆盖“没有面单记录”的待贴标订单。
