# 第六阶段：报价管理企业级优化

## 范围与状态

本阶段只使用现有报价、价格规则和物流渠道结构；未执行数据库迁移、DDL、DML、Flyway 或业务写入。V021/V022、P4-05/P4-06 资源迁移仍为 DEFERRED。

代码范围为 PASS。2026-08-19 已完成真实登录浏览器的只读验收：当前工作台身份显示为“商家管理员一 / 租户管理员”，按项目角色口径属于本阶段的商家操作员验收身份。单元测试和构建不替代该真实会话证据。

## 实现

报价列表的 GET `/api/v1/quotes` 支持报价单号、店铺、渠道、目的国家、状态、创建时间、有效期、分页和排序。查询服务以 `tenant_id + user_id` 调用 Mapper；商家操作员仍需要活动店铺范围，未授权资源统一按既有规范返回 404。排序字段仅允许 `createdAt`、`quoteNo`、`validTo`、`amount`、`status`。

前端报价工作台通过 URL query 恢复并回写同一组白名单筛选项。筛选、分页和排序调用真实 API；加载、空列表与 API 错误继续使用 `DataState`，并显示后端 Trace ID。403/404 不会伪装为无数据。

复制和重新报价先读取受 scope 保护的原报价，仅填入店铺、渠道、目的国家、重量和尺寸。金额、币种、有效期、价格阶梯、规则版本和原版本号不参与新请求；新报价继续由 `POST /api/v1/quotes` 服务端计算、幂等和审计流程产生。

报价详情展示真实快照字段。缺少计算字段显示“未提供”，缺少价格规则配置字段显示“未配置”，不以静态值补齐。创建表单只接受正数、最多三位小数的 kg/cm 输入，不在前端舍入、计算或提交最终金额。

## 转订单与快照

报价转订单服务端继续校验：当前租户、调用人店铺范围、报价状态和有效期、店铺 ACTIVE、渠道 ACTIVE、幂等键和版本。过期报价返回既有拒绝结果“报价已过期，请重新报价”；停用店铺或渠道拒绝新订单。订单创建继续使用不可变报价快照，未回写历史报价、订单、轨迹或账单。

## 验证边界

- 已运行：前端单元测试 23 文件、89 用例；报价 URL 查询、服务参数、复用输入测试；前端构建；JDK 21.0.11 定向 `QuoteControllerWebMvcTest`、`QuoteQueryApplicationServiceTest`、`ShipmentOrderApplicationServiceTest`；敏感信息与 TODO/假数据扫描；`git diff --check`。
- OpenAPI：`listQuotes`、筛选参数和 operationId 存在；使用完整 YAML 内联和块式 operationId 提取后，当前静态契约为 109 个 operationId、109 个唯一值，和 `frontend/docs/openapi-coverage.md` 基线一致。此前仅按行首提取会漏掉内联 operationId，不能作为契约统计方法。
- 浏览器只读验收 PASS：真实报价列表加载；`EXPIRED` 筛选和报价单号升序生效，并回写为 `status=EXPIRED&sortField=quoteNo&sortDirection=ASC`。刷新后 URL 与筛选控件保持一致。已查看一条过期报价详情，展示真实金额、币种、申报/体积/计费重量、体积系数、进位规则、规则版本、有效期和过期状态；“复制报价”“重新报价”入口可见。本轮控制台无新的 ShipFlow `error` 或 `warning`。
- BLOCKED：真实创建报价、重新报价、报价校验和转订单均未执行，因为这些动作可能产生业务写入。浏览器未读取 Cookie、Token 或其他凭证。过期报价转订单的服务端拒绝继续由定向后端测试覆盖。

## 学习笔记

报价查询的资源隔离必须在 Mapper 查询本身完成，而不是让前端过滤列表。复制报价是“复用输入、重新计算输出”，它不能成为复制历史金额、规则版本或有效期的旁路。时间筛选遵循 API ISO 日期时间契约；前端展示时间继续按 Asia/Shanghai 格式化。
