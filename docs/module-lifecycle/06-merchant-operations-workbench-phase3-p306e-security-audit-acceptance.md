# 商家业务员工作台第三阶段 P3-06e 安全、权限、审计与最终验收

更新时间：2026-08-18（Asia/Shanghai）

## 1. 阶段边界与业务流程

本阶段只收口现有商家工作台的权限、安全、审计和会话链路，不扩展业务功能。读取流程为：认证 → scope/角色/权限判定 → `tenant_id` 校验 → `user_id + store_id` 授权范围校验 → 资源归属查询 → 返回脱敏结果；写入流程为：同样的权限链路 → 幂等/版本校验 → 事务写入 → 审计记录。数据库时间继续按 UTC 存储和返回，前端按 `Asia/Shanghai` 展示。

本阶段未执行数据库写入、Flyway、顺丰生产调用或 Git 提交；未恢复 tenant-only 查询，也未修改 `StoreMapper.xml` 或权限数据。

## 2. 权限矩阵收口结果

| 对象/操作 | 商家业务员 | 财务人员 | 租户管理员 | 后端最终边界 |
|---|---|---|---|---|
| 店铺列表/详情 | 仅 active `sys_user_store_scope` | 本租户授权范围 | 本租户 active 店铺 | `tenant_id + user_id + role + store scope`；未授权资源按 404 |
| 工作台概览 | 仅授权店铺聚合 | 按财务权限 | 本租户聚合 | `operations:read`、租户校验、店铺范围 SQL |
| 订单/费用确认申请 | 仅授权店铺；可申请 | 读取/最终确认按权限 | 可作为备用审批人最终确认 | `tenant_id + store_id + resource ownership`；最终确认推进 `READY_FOR_OUTBOUND` |
| 仓库概览/作业 | 无 `warehouse:manage` 时前端隐藏并后端 403 | 按权限 | 仅具备仓库权限时访问 | 不通过前端隐藏替代后端 403 |
| 轨迹查询 | 仅授权订单 | 按权限 | 本租户/权限范围 | 两组轨迹查询均复核订单店铺归属 |
| 异常/索赔 | 按 `exception:read/manage` 和店铺范围 | 按权限 | 按权限 | 异常、处理记录、证据和索赔关联均复核店铺归属 |
| 账单/对账读取 | 仅授权店铺数据 | 按财务权限 | 本租户权限范围 | 批次、明细、对账列表和详情均使用 user/store scope |
| 导出、下载、面单、清关资料 | 无额外后端契约时不显示 | 按正式权限 | 按正式权限 | 任何新增敏感操作必须独立声明权限、资源归属和审计；不能由前端放行 |

结论：前端菜单和路由只提供体验层隐藏，后端 `SecurityConfig`、应用服务和 Mapper/XML 仍是最终授权边界。商家业务员不能通过 URL 篡改订单 ID、店铺 ID、批次 ID、对账 ID 或异常 ID 越权读取。

## 3. 已完成安全收口

### 3.1 账单与对账

- `BillingController` 从 JWT 传入 `tenant_id` 和当前 `user_id`。
- `BillingApplicationService` 对批次、明细、错误行、对账记录列表和详情执行调用者校验。
- `BillingMapper.xml` 的分页、计数和详情访问使用 `sys_user_store_scope`；租户管理员按本租户范围读取，商家业务员只读取授权店铺。
- 未授权批次或对账资源统一返回 `COMMON-1006 / 404`，不泄露资源是否存在。
- 账单导入继续使用文件内容 SHA-256 与 `Idempotency-Key` 组合，不依赖文件名。

### 3.2 轨迹

- `/shipment-orders/{orderId}/tracking`、`/orders/{orderId}/tracking-events` 的查询服务均校验订单所属租户、店铺和当前用户授权范围。
- 跨租户、跨店铺或未授权订单统一按资源不存在处理；轨迹事件仍按事件时间和事件 ID 的既有契约返回，不把未确认事件推断成已签收。

### 3.3 会话安全

- refresh 失败时前端清理内存会话、停止继续刷新，并触发会话失效事件跳转登录页。
- 401 只对允许的请求执行一次 refresh；refresh、login、logout、csrf 路径不递归刷新；并发请求复用同一个 refresh promise。
- 不读取、不输出、不保存 Cookie、Token、Authorization 或密码值。
- Cookie 面板属性和失败清理的浏览器级证据受当前环境能力限制，按 BLOCKED 记录，源码和单元测试仅作为辅助证据。

### 3.4 审计与敏感信息

- 订单创建/修改/取消、费用确认申请/确认、仓库入库/复称/出库、账单导入/对账确认、异常分派/处理记录/证据/索赔、店铺和角色管理等既有关键写操作继续写入 `audit_log`。
- 审计字段只保留租户、操作者、资源、动作、请求/Trace 关联、结果和必要业务原因；证据内容、密码、Token、Cookie、Authorization、私钥和顺丰密钥不进入日志或审计明细。
- 查询类操作不新增审计写入，避免把只读页面刷新误记为业务变更。
