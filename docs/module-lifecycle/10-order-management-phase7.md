# 第七阶段：订单管理

## 业务闭环

报价创建的订单保留不可变报价快照；订单由草稿提交至仓库、复称、费用确认、出库和物流轨迹。所有读取以 `tenant_id + user_id + active sys_user_store_scope` 为边界，越权继续返回既有 404 语义。状态变化由版本号和幂等键保护，审计记录关联请求 Trace ID。

## 已实现

- 订单列表支持订单号、店铺、状态、目的地、渠道、物流单号、创建时间、分页和白名单排序；默认创建时间倒序、ID 倒序。
- 列表返回店铺、渠道、目的地、物流单号、预估/当前/确认费用、币种、计费重量、版本和创建时间。
- 详情聚合订单地址、包裹/商品、费用调整、仓库处理、物流轨迹、异常摘要和由既有事实表组合的 UTC 时间线；不复制或回写历史事实。
- 提交、取消复用 `api_idempotency_record`；相同键且不同参数返回冲突，处理中返回既有处理中错误码。
- CSV 导出复用调用方可见范围，最多 1000 条，UTF-8 BOM；前端支持筛选 URL 恢复、分页、多选和导出入口。

## 数据库变更门禁

V021 仅为订单号、目的地和物流单号筛选新增索引，预计业务行新增/更新/归档均为 0，作用范围为全部租户的既有索引元数据。回滚仅删除 V021 的三个索引。

当前运行库成功 Flyway 历史为 V012，但物理 Schema 已有部分 V013--V020 对象。直接执行 Flyway 会重放缺失历史并可能在既有对象上失败；不得通过修改旧迁移或伪造历史行绕过。V021 的数据库执行因此为 **BLOCKED（等待受控 Flyway 历史校准）**，代码不依赖该索引即可正确运行。

## 学习笔记

订单详情时间线应联合查询审计、仓库、费用、异常和追踪事实，而不是新建另一份可漂移的业务事件表。读模型索引迁移和业务数据变更必须分开说明：本阶段 V021 只影响查询性能，不改写订单、报价、账单、轨迹或快照。
