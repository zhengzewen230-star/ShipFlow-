更新时间：2026-08-17（Asia/Shanghai）

## 1. 阶段边界

本阶段保留已通过的认证、租户/RBAC、店铺、报价、订单、仓库、轨迹、异常与索赔、账单与对账能力。第三阶段先实现商家业务员最常用的运营概览，随后按可验证子阶段扩展工作台模块，不重做已有业务状态机，不重复执行 V018/V019，不启用 Flyway 自动迁移，不连接顺丰生产接口，不提交或推送 Git。

每次只完成一个可验证子阶段。每个子阶段完成时必须提供相关后端测试、前端测试/构建、OpenAPI 静态检查和 `git diff --check` 结果；不得以静态假数据、前端本地计算或伪造空接口替代真实数据。

## 3. P3-02 概览 API 验收字段

概览快照至少包含：

- `timeRange`：请求和实际统计窗口，使用 UTC ISO-8601 起止时间。
- `businessTimeZone`：固定返回 `Asia/Shanghai`，明确“今日”边界。
- `refreshedAt`：服务端生成快照时间，使用 UTC ISO-8601。
- `metrics`：待处理订单、待入库、待复称、待贴标/打单、待出库、在途订单、轨迹异常、待财务处理。
- `todos`：待确认费用、待补充地址、待补充清关资料、待仓库处理、待异常跟进、待对账确认。
- `recentOrders`：订单号、店铺、目的地、当前状态、计费重量、预计费用、顺丰单号、最近更新时间、下一步操作。
- `risks`：报价即将过期、订单长时间未处理、顺丰调用失败、轨迹异常、费用差异、清关资料缺失。

每个指标和待办项必须带可跳转的列表查询条件或稳定的路由目标。最近订单和风险提醒必须带资源 ID，前端只能使用后端返回的跳转目标和筛选条件。

## 4. 验证命令约定

- 后端：使用 JDK 21 执行 Maven 测试，必要时使用独立构建目录，避免覆盖被占用的 `backend/target`。
- 前端：执行 `npm run test:unit` 和 `npm run build`。
- 契约：扫描 OpenAPI path、HTTP method、`operationId` 唯一性和新增 schema/path 对齐。
- 质量：执行 `git diff --check`；LF/CRLF 提示不是 whitespace 错误，但必须记录实际退出码。
- 禁止：Flyway 自动迁移、未经确认的数据库写入、顺丰生产调用、Git commit、Git push。

## 5. 已确认业务规则

1. 报价即将过期、订单长时间未处理均使用平台默认 24 小时阈值，后续保留配置化扩展点。
2. “待财务处理”保留聚合指标，并拆分为 `PENDING_FEE_CONFIRMATION`、`BILL_IMPORT_ERRORS`、`RECONCILIATION_DIFFERENCE`、`PENDING_FINANCE_REVIEW`。
3. 商家业务员只看 ACTIVE 授权店铺，租户管理员看本租户全部 ACTIVE 店铺；后端不得信任请求中的 tenantId 扩权。

## 6. P3-06e 验收门槛

- 账单批次、账单明细、对账记录和两组轨迹查询必须同时校验 `tenant_id + user_id + store scope`；未授权资源使用 404 隐藏存在性。
- refresh 失败必须清理前端内存会话并停止无限重试；Cookie 值、Token、Authorization 和密码不得进入日志或文档。
- 关键写操作沿用现有 `audit_log` 链路；审计仅记录脱敏元数据和 Trace/请求关联，不记录证据内容或认证材料。
- 运行前端测试/构建、JDK 21.0.11 后端定向测试、OpenAPI 静态检查、敏感信息与假数据扫描和 `git diff --check` 后，才可评估 P3-06e 是否结案。
- 401、网络失败、409/422/500、Cookie 面板等无法安全制造或读取的浏览器场景必须标记 BLOCKED，不得转换为 PASS。
