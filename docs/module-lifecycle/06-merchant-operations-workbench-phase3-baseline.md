# 商家业务员工作台第三阶段基线

更新时间：2026-08-17（Asia/Shanghai）  
适用范围：运营概览重做及后续商家业务员企业级工作台子阶段。

## 1. 参与方与业务流程

参与方包括商家业务员、租户管理员、财务人员、仓库操作员、客服/异常处理人员和后端服务。用户登录后，后端从认证上下文取得 `tenant_id` 与用户 ID；服务端依据角色权限和 `store_id` 资源归属建立可见范围；概览服务在同一查询窗口内读取订单、仓库、物流、轨迹、异常、账单/对账和报价数据，生成一个只读快照；前端展示快照并把指标、待办、风险和最近订单的点击行为跳转到既有列表查询。

刷新重新读取同一个概览快照接口。时间范围切换重新以指定窗口查询。列表页使用后端返回的筛选条件，并在列表自身再次校验 `tenant_id`、`store_id`、角色和资源归属。概览不直接改变订单、费用、物流、异常或账单状态。

## 2. 已核对的现有能力与缺口

修改前已核对当前状态机、权限、数据库表、OpenAPI、后端 operations 模块和前端路由：

- 订单已有 `DRAFT`、`PENDING_INBOUND`、`INBOUND`、`PENDING_PRICE_CONFIRMATION`、`READY_FOR_OUTBOUND`、`OUTBOUND`、`IN_TRANSIT`、`DELIVERED`、`CANCELLED`、`RETURNED`、`LOST` 状态。
- 仓库已有真实概览查询，能够识别待入库、待复称、待面单/贴标、待交接、待出库、在途和轨迹异常；`LABEL_READY` 是面单/贴标状态契约，不新增第二套标签状态。
- 费用确认已由财务人员最终执行，租户管理员可备用确认，商家业务员只能提交申请；成功后订单进入 `READY_FOR_OUTBOUND`。
- 异常已有责任方、处理记录、证据附件、索赔关联和租户/店铺资源校验；账单已有文件内容哈希与 `Idempotency-Key` 组合幂等。
- 当前 `/api/v1/operations/summary` 只返回租户级订单状态聚合，`/api/v1/operations/todos` 只返回部分待办；缺少用户/店铺范围、统计时间窗口、刷新时间、最近订单、风险提醒和统一快照。
- 当前 Dashboard 主要展示摘要数据，订单、仓库、轨迹、异常和账单列表使用不同 API；第三阶段必须避免概览与列表各自计算导致口径分叉。

## 3. 数据隔离和权限基线

所有概览查询必须满足：

1. `tenant_id` 来自认证上下文，不能由前端请求体覆盖；所有业务表查询带租户条件。
2. 订单、报价、仓库、轨迹、异常、索赔和账单关联数据必须沿订单 `store_id` 过滤。
3. 商家业务员只允许读取 `sys_user_store_scope` 中 `ACTIVE` 的店铺；租户管理员可读取本租户全部 `ACTIVE` 店铺；其他角色按既有 RBAC 和资源范围执行。
4. 跨租户、跨店铺或资源不存在统一按既有错误契约处理；前端不能通过改变 URL 中的 ID 绕过后端范围校验。
5. 权限不足必须呈现权限不足状态；API 失败必须呈现失败状态和重试入口，不得降级为静态演示数据。

## 4. 指标和待办口径基线

### 4.1 今日核心指标

| 展示项 | 后端口径 | 目标列表 |
|---|---|---|
| 待处理订单 | 可见店铺中未取消、未完成且需要业务员下一步处理的订单 | 订单列表，带状态筛选 |
| 待入库 | `PENDING_INBOUND` | 仓库作业列表 |
| 待复称 | `INBOUND` 且等待复称 | 仓库作业列表 |
| 待贴标/打单 | 订单已可出库但物流商面单状态不是 `LABEL_READY` | 仓库/物流作业列表 |
| 待出库 | 订单状态 `READY_FOR_OUTBOUND` 且面单状态为 `LABEL_READY` | 仓库作业列表 |
| 在途订单 | 订单状态 `IN_TRANSIT` | 订单/轨迹列表 |
| 轨迹异常 | 可见范围内轨迹事件 `RETRY` 或 `REJECTED`，或既有异常判定 | 轨迹/异常列表 |
| 待财务处理 | 费用确认待最终确认、费用差异待处理或待对账确认，子口径必须可区分 | 账单/对账或订单财务列表 |

“今日”按 `Asia/Shanghai` 自然日计算，再转换为 UTC 时间窗口传给数据库；数据库继续按 UTC 存储。所有指标返回实际 `from`、`to`，不能只返回“今日”文字。

### 4.2 我的待办

待确认费用来自费用调整 `PENDING_CONFIRMATION/REQUESTED`；待补充地址来自订单地址缺失或被标记为补充；待补充清关资料来自物流/仓库资料缺失；待仓库处理来自仓库状态待入库、待复称、待贴标/打单或待出库；待异常跟进来自未关闭异常及其责任处理状态；待对账确认来自 `PENDING_CONFIRMATION` 对账记录。每项必须返回真实数量和跳转筛选条件。

### 4.3 最近订单

按可见范围内订单最近更新时间倒序，返回订单号、店铺名称、目的地、当前状态、计费重量、预计费用、顺丰单号、最近更新时间和下一步操作。金额使用 `BigDecimal`，重量沿用现有订单投影单位契约；时间接口返回 UTC，前端按 `Asia/Shanghai` 展示。

### 4.4 风险提醒

风险只由后端真实规则生成：报价有效期临近、订单超过处理阈值、顺丰调用失败、轨迹异常、费用差异和清关资料缺失。每条风险至少包含类型、等级、标题、资源 ID、发生时间、说明和跳转条件；没有风险返回空数组并显示空状态，不显示虚构提醒。

## 5. 统一快照和一致性约束

概览接口必须在一次服务调用中固定 `refreshedAt` 和实际时间窗口，并由同一查询条件生成指标、待办、最近订单和风险。各模块可通过明确的只读查询实现，但不得让前端把多个独立响应自行相加后冒充统一统计。列表跳转使用快照返回的资源筛选条件；列表可能在跳转后因数据变化而更新，前端应显示列表自身刷新时间。

统计卡、待办和列表出现同一业务对象时，必须在设计文档中标明是否为同一集合或不同子口径；例如“待财务处理”可以是多个财务子口径的合计，但待办项必须分别提供子项，避免用户无法解释数量差异。

## 6. 状态和异常路径

- 加载中：保留页面骨架和上次已确认的刷新时间，不显示新请求尚未得到的数字。
- 空数据：显示明确空状态，数量为真实的零或空数组。
- API 失败：显示后端错误文案、失败时间和重试按钮；不回退到静态数据。
- 权限不足：显示无权查看当前模块，并隐藏不可用跳转按钮；不通过前端权限判断代替后端校验。
- 店铺范围变化：重新请求概览，旧快照不继续作为当前数据使用。
- 时间窗口切换：清除旧窗口的加载结果，成功后同时更新指标、待办、最近订单、风险和刷新时间。

## 7. 非目标和实施禁令

本基线不新增订单、费用确认、物流商面单、账单导入、异常状态机或索赔状态机；不重复定义 V018/V019 的数据库结构。第三阶段概览优先使用现有表和查询能力，只有在 P3-02 证明查询无法满足真实口径时，才提出最小数据库结构并另行确认。当前不启用 Flyway 自动迁移，不执行任何数据库迁移，不连接顺丰生产接口，不提交或推送 Git。
