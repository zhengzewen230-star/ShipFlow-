# 商家业务员工作台第三阶段 P3-04 前端实现

更新时间：2026-08-17（Asia/Shanghai）  
阶段状态：已完成前端运营概览实现，等待进入下一子阶段确认。

## 1. 子阶段范围与业务流程

本子阶段只实现商家业务员工作台的前端运营概览，入口为租户侧 Dashboard。页面通过一次 `GET /api/v1/operations/workbench` 获取同一刷新快照，再展示核心指标、待办、最近订单和风险提醒；点击项使用后端返回的白名单路由和筛选条件进入现有订单、报价、仓库、轨迹、异常或财务列表。

参与方和边界保持 P3-02/P3-03 约定：商家业务员只能查看后端按 `tenant_id` 与 ACTIVE 授权 `store_id` 计算出的数据；租户管理员可查看本租户 ACTIVE 店铺；前端权限判断只负责界面提示，不能替代后端 RBAC、资源归属和店铺隔离。费用确认仍由业务员提交申请、财务最终执行，工作台不推进任何业务状态。

## 2. 已实现内容

### 2.1 运营概览

- 8 个核心指标：待处理订单、待入库、待复称、待贴标/打单、待出库、在途订单、轨迹异常、待财务处理。
- “待财务处理”继续展示后端返回的四项拆分：待确认费用、账单导入错误、费用对账差异、待财务复核；前端不重新统计。
- 6 类“我的待办”：待确认费用、待补充地址、待补充清关资料、待仓库处理、待异常跟进、待对账确认。
- 最近订单展示订单号、店铺、目的地、状态、计费重量、预计费用、顺丰单号、更新时间和下一步操作。
- 风险提醒展示报价即将过期、长时间未处理订单、顺丰调用失败、轨迹异常、费用差异和清关资料缺失等后端风险类型。
- 支持 TODAY、LAST_7_DAYS、LAST_30_DAYS 时间范围、刷新、空数据、加载中、重试和列表跳转。

### 2.2 前端契约与展示规则

| 领域 | 实现规则 |
|---|---|
| API | 仅调用 `GET /api/v1/operations/workbench`；不加入静态业务数据。 |
| 权限 | 无 `operations:read` 显示权限提示；401 显示会话失效并引导登录；403 显示无权访问；HTTP 层保留既有会话刷新机制。 |
| 跳转 | 只接受后端返回且以 `/app/` 开头的路由，查询参数过滤空值，防止前端自行扩大资源范围。 |
| 时间 | 接口时间按 UTC 接收，使用 `Intl.DateTimeFormat` 以 `Asia/Shanghai` 展示；统计窗口和刷新时间均可见。 |
| 金额 | 沿用后端金额字符串/数值语义，前端只做两位小数展示和币种拼接，不重新计算。 |
| 重量 | 沿用工作台接口的 kg 单位，前端只格式化为三位小数，不套用订单投影中其他字段的克转千克规则。 |
| 一致性 | 指标、待办、最近订单和风险来自同一 `refreshedAt` 快照；前端不从列表重新合计。 |
