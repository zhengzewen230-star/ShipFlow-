# 租户员工身份选择学习笔记

## 业务流程

租户管理员在员工管理页面填写姓名、用户名和临时密码，从后端返回的活动租户角色中选择一个身份。前端将所选角色的 ID 以单元素 `roleIds` 数组提交给用户创建接口。

## 参与方与边界

- 租户管理员：仅在具有 `user:manage` 权限时可创建员工。
- 前端：展示角色名称，不展示或手工录入角色 ID；不决定角色是否可分配。
- 后端：校验角色处于 `TENANT` 作用域、活动状态、未删除且属于当前租户。

## 异常路径

- 角色列表加载失败：创建表单不应把任意文本当作角色提交。
- 未选择有效角色：前端阻止提交并提示选择身份角色。
- 角色已停用、删除或不属于当前租户：后端拒绝请求，前端显示服务端错误信息。

## 后续治理问题

当前接口允许有 `user:manage` 权限的管理员选择所有当前租户的活动角色。是否允许创建额外的租户管理员、以及如何避免最后一个租户管理员被移除，应在独立的角色治理模块中形成明确规则和审计要求。
