# 正式报价有效期与时区学习笔记

## 时间规则

- 报价创建和校验统一使用 UTC 时钟。
- 正式报价的有效期为创建时刻起 30 分钟。
- API 使用带 `Z` 的 UTC 时间戳传输；前端向中国用户展示为北京时间（Asia/Shanghai）。

## 运行时状态

数据库中的 `VALID` 表示报价未被取消；报价是否仍可消费还必须比较 `valid_to` 与当前 UTC 时间。

- `VALID` 且 `valid_to` 在未来：对外显示为有效。
- `VALID` 且 `valid_to` 已到：对外显示为已过期。
- `CANCELLED`：始终显示为已取消。

列表、详情、有效性校验和订单创建均使用同一时效规则。订单创建仍由服务端在事务内最终判定，前端展示不能替代该校验。

## 异常路径

报价在用户打开详情后到提交创建订单前可能过期。前端应提示重新获取正式报价；服务端拒绝该请求，避免过期金额被消费。
