# 前端枚举展示与控件统一

## 目标

后端枚举和表单提交继续使用稳定的英文业务编码；浏览器只显示统一的中文业务名称、可访问状态文字和企业级控件样式。

## 实施要点

- `display.ts` 集中维护字段名、状态、异常类型、责任方、平台和费用类型映射；未知编码显示“未知状态”或“未配置”，仅在开发诊断中记录原编码。
- 列表展示可使用只读投影，编辑表单和 API payload 必须保留原始编码，避免把中文文案写回业务接口。
- `StatusBadge` 同时保留图标、文字和 `aria-label`，不以颜色作为唯一状态表达。
- 公共样式仅作用于 `.app-content`，统一按钮、排序、分页、输入框及键盘焦点，不影响登录页左侧品牌区域。
- 遗留页面中用户可见的 `reconciliation` 与 `fee_adjustment` 技术文本由根展示层替换为中文，不改变 DOM 表单 value 或请求数据。

## 验证

应同时运行类型检查、单元测试和生产构建，并通过已登录浏览器确认店铺、异常、账单、订单、轨迹页面没有暴露上述英文枚举；检查复制控件、分页禁用态和键盘焦点保持可用。
