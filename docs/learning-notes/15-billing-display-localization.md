# 账单展示中文化：费用类型与导入错误

## 目标

账单 API 继续使用稳定的英文费用类型、处理状态与错误编码/消息；界面渲染层统一将可识别的值显示为中文，避免将内部英文枚举暴露给操作人员。

## 实现边界

- `frontend/src/utils/display.ts` 是唯一的展示映射入口。
- `FREIGHT`、`INVALID` 与错误处理状态均在读取响应后映射，不修改请求参数、数据库值或后端校验。
- 已知账单导入校验原因保留动态脱敏编号，仅翻译固定文字；未知英文原因只显示“账单导入校验失败（原因未配置）”，并在开发环境记录可诊断信息。
- `FinanceView.vue` 的账单明细和导入错误明细禁止直接插值这些原始字段，必须调用共享 `format`/`formatMoney`。

## 回归验证

- `display.spec.ts` 覆盖费用类型、处理状态和四类导入错误原因。
- `erpControlPresentation.spec.ts` 断言账单页面仍走公共格式化入口，防止模板回退为原始英文直出。

## 待确认问题

当前浏览器会话无财务查询权限，实际账单详情页面返回 403。需要拥有账单查询权限的测试账号完成一次真实页面验收，确认生产数据中所有后端错误消息均属于已配置模板或有产品认可的中文兜底文案。
