# 第十一阶段：统一企业级交互体验学习笔记

## 业务流程

1. 用户通过受保护路由进入业务页面，路由守卫先恢复会话并校验权限。
2. 列表页从 URL 恢复筛选、分页、排序和必要的详情标识，再按当前租户与店铺范围请求后端真实数据。
3. 页面明确区分加载中、空数据、请求失败、无权限和会话过期；错误同时展示中文原因、错误码和 Trace ID。
4. 表单先执行字段级校验，高风险操作再进入统一确认对话框。写请求继续沿用原有权限、Idempotency-Key、version、事务与审计契约。
5. 成功后展示统一通知并重新读取真实数据；失败时保留用户输入并显示后端原因，不伪造状态、金额或业务结果。

## 参与方与职责

- 用户：筛选、分页、查看详情、复制业务编号，确认高风险操作。
- Vue 页面：维护 URL 可恢复状态、字段校验、处理中状态和可访问性交互。
- 公共组件与 composable：统一数据状态、操作错误、通知、状态徽标、复制、分页和二次确认。
- HTTP 客户端与路由守卫：统一中文错误转换、单次刷新重试、会话过期跳转及原请求终止。
- 后端：继续负责租户/店铺权限、金额计算、状态机、幂等、乐观锁、审计与 Trace ID。

## 关键规则与异常路径

- 401：刷新 Token 只允许一次；刷新失败终止原请求并跳转登录页，禁止无限重试。
- 403、404、409、422、500 和网络失败：不得静默吞掉，页面或操作区域显示中文原因、错误码与 Trace ID（存在时）。
- 列表状态写入 URL；刷新、深链接及浏览器前进/后退时可恢复。
- 状态不能只依赖颜色，统一状态组件同时提供文字、图标和 `aria-label`。
- 取消订单、提交订单、关闭异常、财务确认和对账确认/驳回等高风险操作使用统一二次确认。
- 复制功能只复制可见的订单号、报价号、异常号或 Trace ID，不访问浏览器凭证或会话存储。
- 响应式页面允许表格区域内部滚动，页面本身不得产生横向溢出；键盘焦点保持可见。

## 公共实现

- `DataState`：加载骨架、空状态、失败、无权限、会话过期及重试入口。
- `ActionError`：操作级中文原因、错误码和 Trace ID。
- `NotificationHost`：成功/失败反馈及可关闭通知。
- `ConfirmDialog` + `useConfirmAction`：统一高风险操作确认、焦点与 Escape 取消。
- `CopyTextButton`、`StatusBadge`、`ListPagination`：复制、非纯颜色状态和一致分页。
- `http.ts` 与路由守卫：统一 API 错误和会话过期处理，同时保留 CSRF 与原有认证机制。

- 前端类型检查通过。
- 前端单元测试通过：27 个测试文件、100 个测试。
- 前端生产构建通过。

- 真实财务、租户管理员、仓库操作员和平台管理员会话覆盖了概览、用户、店铺、角色权限、物流、报价、订单、轨迹、异常、账单、审计、仓库、租户、入驻审核和访客线索页面。

- 真实路由验证了无权限页面的 403 中文提示和未知路由的 404 中文提示；HTTP 单元测试覆盖 401、403、404、409、422、500 与网络失败的中文转换、Trace ID 和刷新失败单次终止。
