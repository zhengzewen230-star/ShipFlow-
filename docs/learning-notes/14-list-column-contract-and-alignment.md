# 列表列契约与表头对齐

## 问题

`table-layout: auto` 会让长订单号、文件名、状态标签或操作按钮参与每次列宽计算。即使同一行内的表头和数据暂时对齐，数据集变化后仍会造成视觉错位。

## 解决方案

- 所有业务 `.data-table` 使用 `table-layout: fixed`、`width: 100%` 和统一的 `box-sizing`、内边距、行高、垂直对齐。
- 默认单元格不换行、超出时省略；移动端由 `.data-table-wrap` 承担横向滚动，主内容区不产生横向溢出。
- 异常列表的 13 列使用明确宽度比例，状态、类型、负责人、索赔、财务确认、版本与操作列在表头和内容中共同居中。
- 复制控件绝对定位在单元格内部，避免复制图标参与表格宽度计算或推动长单号。
- 公共展示层会依据中文表头给“状态”等中心列及同列数据加上同一语义类，避免纯文本表头仍按默认左对齐、而状态徽章已经居中的跨页面偏差。

## 验证方式

在真实浏览器中同时读取首行 `th/td` 的 left/width 边界；只有每一列边界一致才算通过。对店铺、订单和账单列表也验证固定布局、无主容器溢出和单元格省略策略。
