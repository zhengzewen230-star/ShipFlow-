# 第九阶段异常与索赔闭环学习笔记

## 业务流程与参与方

- 商户有权限的操作人创建异常，并在租户和店铺范围内查询、分配负责人、补充处理记录和证据。
- 当前负责人使用 `exception_case.assigned_to_user_id` 保存；负责人变更同时写审计，保留旧负责人、新负责人、操作人、原因、请求标识和追踪标识。
- 物流商反馈由异常状态表达；索赔审核保存审核结果、审核金额与审核原因；财务人员完成财务确认后，异常才具备解决条件。
- 所有时间以 UTC 进行接口传输和稳定排序，金额使用 `BigDecimal`，币种作为独立字段保存。

## 状态与规则

严格状态图为：

1. `OPEN -> PROCESSING`
2. `PROCESSING -> WAITING_PROVIDER_FEEDBACK`
3. `WAITING_PROVIDER_FEEDBACK -> PROCESSING`
4. `PROCESSING -> PENDING_FINANCE_CONFIRMATION`
5. `PENDING_FINANCE_CONFIRMATION -> RESOLVED`
6. `RESOLVED -> CLOSED`

`PENDING_FINANCE_CONFIRMATION -> CLOSED` 必须拒绝。进入 `RESOLVED` 前必须满足证据、处理记录、索赔结果和财务确认条件；进入 `CLOSED` 前索赔必须关闭。异常关闭后，分配、状态更新、处理记录、证据、索赔创建、索赔结果和财务确认均拒绝。

索赔部分批准必须保存实际批准金额，拒绝必须保存审核原因。创建索赔会同步异常到待财务确认状态，不能让异常停留在与索赔无关的状态。

## 幂等、并发与审计

- 创建、分配、状态推进、处理记录、证据上传、索赔创建、索赔结果、财务确认和关闭统一复用 `api_idempotency_record`。
- 相同键与相同请求返回原结果；相同键与不同请求返回冲突；处理中的请求返回明确业务错误。
- 写操作携带 `version` 并以受影响行数判断乐观锁冲突，重复请求不得重复推进状态、插入业务记录或写审计。
- 审计与统一时间线包含操作人、状态前后值、关联资源、发生时间以及 Trace ID 或 requestId；不记录附件内容、认证信息或供应商完整报文。

## 本轮验证结论

- JDK 21.0.11、独立 Maven 输出目录下，定向测试与全量 423 个后端测试已通过。
- 前端类型检查、25 个测试文件中的 94 个单元测试和生产构建已通过。
- Chrome 中已验证专用异常页面、认证状态、完整列表筛选、排序与空态；当前租户异常列表为 0 条，订单页面也没有创建异常入口，因此无法在浏览器中继续执行分配、处理、证据、索赔、财务确认和关闭链路。
- 因浏览器端到端门槛未满足，V022 保持未执行；不得用静态测试或空列表页面替代写流程验收。
