# 第十一阶段：企业级 ERP 交互重构学习笔记

日期：2026-08-28
时区：Asia/Shanghai（UTC+08:00）

## 业务流程

ShipFlow 的运营人员从真实工作台 KPI、待办或风险进入订单、仓库、轨迹、异常与索赔、账单与对账列表。页面跳转只携带后端支持的筛选条件，租户与店铺范围仍由后端身份上下文决定。最近访问页签保存完整深链接，因此浏览器返回、前进和刷新不会丢失分页、排序或筛选上下文。

## 参与方与规则

- 平台管理员：租户、入驻申请、访客线索、公共物流资料和平台审计。
- 租户管理员/运营：店铺、报价、订单、轨迹、异常、账单、对账和租户审计。
- 仓库操作员：订单、仓库和轨迹；不可进入财务页面。
- 财务与客服角色继续沿用既有权限，不由前端导航扩大授权。
- 所有 KPI、待办、风险和最近订单均来自 `operations/workbench` 或仓库概览 API；前端不生成业务数量或金额。

## 状态与异常路径

- 加载、空数据、请求失败、无权限和会话过期继续使用既有公共状态组件。
- 状态标签同时使用文字、图标语义和颜色；编号与 Trace ID 使用公共复制组件。
- 高风险写操作继续走既有确认框、幂等键、版本锁、审计与 Trace ID，不在本次视觉重构中改变状态机。
- 真实浏览器发现工作台伪状态 `PENDING_FEE_CONFIRMATION` 曾被直接作为订单状态发送，导致 `COMMON-1001`；修复为后端正式 `workbenchFilter`，并增加回归测试。
- 移动导航和全局搜索增加显式 Enter/Space/Escape 键盘契约，避免只依赖浏览器默认表单行为。
