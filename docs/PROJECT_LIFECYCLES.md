# ShipFlow 开发与测试全生命周期

本文件是项目级索引。模块详细设计、迁移记录和验收证据应继续写入 `docs/module-lifecycle/` 与对应学习笔记。

## 1. 后端开发生命周期

1. 明确参与方、状态变化、租户/店铺权限、异常路径和审计事件。
2. 设计/更新 Domain、状态机、DTO、错误码、OpenAPI 和权限策略。
3. 实现 Service 的事务、幂等、版本锁、UTC 时间处理和 `BigDecimal` 金额规则。
4. 同步 Controller、Mapper 接口和 Mapper XML；所有查询必须附带租户及必要的店铺范围。
5. 编写单元、WebMvc、Mapper XML 和必要的集成测试，覆盖成功、401、403、404、409、422、500、重复请求和异常恢复。
6. 运行 JDK 21 Maven 全量测试；记录真实结果、Trace ID 和未覆盖的运行态边界。

## 2. 前端开发生命周期

1. 从 OpenAPI 和后端响应定义 typed service，不在 UI 中猜测金额、状态、指标或权限。
2. 路由按 scope/permission 保护；请求统一处理 CSRF、刷新会话、Trace ID 和稳定错误码。
3. 页面实现加载、空态、失败、401、403、分页、排序、筛选与刷新后 query 保持。
4. 写操作使用防重复提交、处理中反馈、二次确认（高风险操作）和可复制 Trace ID。
5. 中文枚举、状态标签、表格列、键盘可用性和响应式布局由共享组件统一。
6. 运行 `npm run typecheck`、`npm run test:unit`、`npm run build`，再以真实登录会话完成浏览器验收。

## 3. 数据库与 Flyway 生命周期

1. 先只读确认 `SELECT DATABASE()`、MySQL 版本、时区、`flyway_schema_history` 和现有表/索引/约束。
2. 设计新表/字段时写明 tenant_id、主键、唯一约束、外键、索引、数据影响量、备份及回滚。
3. 新增顺序迁移，不修改历史迁移，不删除历史数据，不伪造迁移成功。
4. 同步 `database/schema.sql`、Domain、Mapper XML、DTO、OpenAPI 和测试。
5. 在隔离数据库执行迁移并验证 schema、关键数据、查询计划和回滚步骤；共享/生产环境仅在变更批准后执行。

## 4. 接口自动化测试生命周期

1. 从 OpenAPI 建立用例矩阵，绑定前置数据、角色、租户、店铺范围和断言。
2. 每个用例同时维护 HTTP 断言与数据库断言；禁止依赖固定 sleep，异步流程使用轮询。
3. 覆盖认证、权限、幂等、版本冲突、业务校验、超时、供应商失败、重复和乱序回调。
4. 测试环境通过环境变量提供凭据；报告只保留脱敏请求标识、错误码、Trace ID 和结果。
5. 在 CI 中产出报告，失败不得伪造成功；按测试数据生命周期清理隔离数据，不对生产数据执行清理脚本。

## 5. GitHub 发布生命周期

1. `git status --short` 审查工作树；只显式选择源代码、迁移、测试、OpenAPI 和文档。
2. 使用 `.gitignore` 排除密钥、环境文件、数据库文件、构建目录、缓存、报告与临时目录。
3. 执行 `git diff --check` 以及与本次变更相关的后端/前端检查。
4. 暂存后复核 `git diff --cached --check` 与 `git diff --cached --name-only`，确认没有无用或敏感内容。
5. 创建清晰提交，推送前验证 GitHub 身份与远程分支，推送后核对远程 SHA；必要时创建草稿 PR。
