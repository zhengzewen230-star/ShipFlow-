# ShipFlow 第一版业务边界

## 1. 目标客户

ShipFlow 第一版面向需要向日本、美国和欧洲发货的中国跨境商家，模拟商家从物流下单、仓库处理、物流商运输到费用对账和异常索赔的完整业务链路。

## 2. 系统角色

1. 平台管理员：负责平台级租户、用户和基础配置管理。
2. 商家管理员：负责本租户的用户、物流渠道和业务配置管理。
3. 商家操作员：负责物流订单创建、履约跟踪和异常处理等日常操作。
4. 仓库人员：负责入库、复称、出库和仓库作业结果确认。
5. 财务人员：负责账单导入、费用核对、差异处理和结算确认。
6. 物流商系统：作为外部协作方，提供渠道能力、轨迹回调和账单等模拟数据。

所有业务角色都必须遵守租户边界和权限边界；物流商系统属于外部系统角色，通过 Mock 方式参与第一版流程。

## 3. 第一版业务范围

### 3.1 租户与用户

一个租户代表一个签约商家主体；一个租户可以管理多个店铺、品牌或平台账号。平台管理员负责创建租户和初始商家管理员，商家管理员负责管理本租户用户和角色。所有跨租户访问必须被禁止，并记录安全日志。

### 3.2 物流商与物流渠道

维护物流商及其可用渠道，记录渠道的服务区域、基础属性和启停状态，为报价和物流订单提供渠道来源。

### 3.3 运费报价

同时支持商家申报重量和体积重量。报价阶段的计费重量取商家申报重量与体积重量的最大值。体积系数和重量进位规则由物流渠道配置。报价必须包含有效期和价格规则版本，创建订单时必须传入有效 `quote_id`。订单保存不可变的报价快照，渠道价格修改不得影响历史订单。

### 3.4 物流订单

承载商家发货请求及履约主线，记录订单、包裹、收发货信息、选择的物流渠道、有效报价和关键状态变化。订单必须遵循既定状态机，处理重复提交、非法状态操作和费用确认分支。

### 3.5 仓库入库与复称

入库后由仓库人员测量并保存仓库实际重量和尺寸。复称后的仓库实际体积重量依据渠道规则计算，复称后的计费重量取仓库实际重量与仓库实际体积重量的最大值，并自动重新计算费用。费用不变时自动继续；费用降低时自动更新并记录调整；费用增加时订单进入 `PENDING_PRICE_CONFIRMATION`，商家确认新价格后才允许出库。

### 3.6 仓库出库

记录拣配、出库确认及交接物流商等关键节点，形成从仓库作业到物流履约的可追溯连接。

### 3.7 物流轨迹回调

通过 Mock 物流商系统接收轨迹事件。回调事件使用 `provider_id + tracking_no + event_id` 幂等去重，所有合法轨迹都需要保存并按 `event_time` 展示。订单状态只能按状态机向前推进，迟到事件不得使订单状态回退；同时保存原始报文、`event_time` 和 `received_time`。重复事件返回幂等成功，但不能重复保存业务影响、重复推进状态或重复创建审计记录。非法跳转记录异常并支持重试。

### 3.8 账单导入

第一版使用统一 CSV 模板导入物流商账单，系统内部转换为统一账单明细 DTO。必须记录导入批次、文件摘要、成功数量、失败数量和行级错误，为费用对账提供可追溯来源数据。

### 3.9 费用对账

将报价、仓库复称结果、订单履约数据与物流商账单进行比对，识别金额差异、计费依据差异和缺失数据。金额完全一致时系统自动关闭对账记录；任何非零差异都必须由财务人员确认后关闭。第一版不实现小额差异自动关闭，财务处理方式、备注和审计日志必须完整记录。

### 3.10 异常件与索赔

记录丢失、破损、延误、拒收等异常件，支持异常状态跟踪、责任信息、证据记录和模拟索赔处理结果。

### 3.11 审计日志

记录关键业务操作、操作者、租户、时间、请求关联信息和结果，支持问题追溯和测试验证。

## 4. 第一版暂不实现

1. 真实海关系统。
2. 真实支付宝、微信或其他支付。
3. 真实物流商账号和生产接口。
4. 真实汇率接口。
5. 完整前端页面。
6. 微服务拆分。
7. Kubernetes。
8. 复杂财务发票和税务申报。

此外，项目不接入真实客户数据，不实现真实地图导航、实时轨迹采集、硬件设备接入、面向公网的商业化运营和高可用生产部署，也不替代生产级计费合规、税务申报或财务总账系统。

## 5. 边界内的工程约束

- 金额统一使用 `BigDecimal` 表达和计算。
- 时间必须带有明确时区。
- 所有写接口考虑幂等、事务和重复请求。
- 所有业务表考虑 `tenant_id`。
- 核心测试同时进行接口断言和数据库断言。
- 异步业务使用轮询验证，禁止固定长时间等待。
- 外部物流商能力通过 Mock 服务模拟，不连接真实生产接口。

## 6. 范围确认结论

本文件将第一版范围限定为“面向中国跨境商家、覆盖日本/美国/欧洲目的地的物流履约与费用结算仿真”。后续新增模块、外部系统或生产化能力，都需要先重新确认业务边界，不应默认纳入第一版。
