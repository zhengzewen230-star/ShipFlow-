# 商家店铺范围权限学习笔记

## 结论

- 商家业务员的店铺可见范围不能由 `tenant_id` 单独决定，必须同时校验调用用户、租户、角色、有效店铺和 `sys_user_store_scope`。
- 租户管理员、财务、仓库和客服等既有租户级角色可按当前权限矩阵查看本租户有效店铺；`MERCHANT_OPERATOR` 只查看被授权的有效店铺。
- 详情、列表分页总数、更新和状态变更必须使用一致的资源归属规则。未授权资源按统一资源不存在错误处理，避免跨店铺枚举。
- `storeIds=0` 是合法空授权范围的只读结果：工作台返回空集合和零指标，不能用静态数据或通用 500 掩盖权限边界。

## 实现要点

- Store Mapper 增加带 `userId` 的 `findByIdForUser`、`pageForUser` 和 `countForUser` 查询。
- 查询保留 `tenant_id`、`deleted=0`、有效状态、筛选和分页条件，并在 SQL 中校验用户和角色授权。
- 控制器从 JWT 传递 `tenant_id` 与 `userId`；服务层在详情和写操作前再次执行资源归属检查。
- 本模块不新增数据库迁移、不修改数据库权限数据、不连接顺丰生产接口。

## 验证边界

- JDK 21.0.11 下店铺定向测试 10/10、后端编译通过；前端 52/52 与构建通过；OpenAPI 106 个 operation、匿名 GET 56/56、写操作 50 个跳过。
- 当前受控浏览器可打开登录页，但本次验收进程不可读取测试密码，因此未将未登录页面结果当作真实业务验收；P3-05 仍阻塞。
