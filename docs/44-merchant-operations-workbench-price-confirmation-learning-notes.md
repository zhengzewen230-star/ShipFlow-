# 商家业务员工作台费用确认模块学习笔记

更新时间：2026-08-17（Asia/Shanghai）

## 1. 本次模块

本次只实现第二阶段的“订单费用确认与状态契约”。仓库复称产生费用上涨时，订单保持在 `PENDING_PRICE_CONFIRMATION`，商家业务员提交申请，财务人员最终确认，租户管理员作为备用审批人；确认成功后订单进入 `READY_FOR_OUTBOUND`。

## 2. 关键业务规则

- 商家业务员只能提交申请，不能调用最终确认；其订单读取和申请都必须命中 `sys_user_store_scope` 中的启用店铺。
- 财务人员是主要最终确认角色，租户管理员可确认本租户全部启用店铺，但所有角色都必须重新校验 `tenant_id`、`store_id`、订单和费用调整归属。
- 最终确认只接受 `INCREASE` 调整，`expectedFee` 必须等于服务端 `after_amount`，并使用订单 `version` 做乐观锁；订单和费用调整在同一事务中更新。
- 相同 `Idempotency-Key` 和请求体哈希重复请求重放原结果；同一幂等键复用不同请求体返回冲突，不能只依赖文件名或前端状态。
- `LABEL_READY` 只表示物流商面单/贴标状态，不加入订单状态机。
- 数据库时间按 UTC 保存，API 时间按 UTC ISO-8601 返回，前端展示使用 `Asia/Shanghai`。

## 3. 实现要点

- 复用 `shipment_order`、`fee_adjustment`、`audit_log` 和 `api_idempotency_record`；只补充费用调整申请字段和最小的 `sys_user_store_scope` 关系。
- 查询、申请和确认分别在 Controller、应用服务和 Mapper SQL 保留租户/店铺边界，不能用前端隐藏按钮替代后端授权。
- 费用确认成功条件必须同时满足订单状态、调整状态、调整类型、金额和版本；任一条件失败不得写入订单或确认记录。
- 迁移文件、`schema.sql`、`init_data.sql`、OpenAPI、SecurityConfig、前端 service 和测试必须表达同一状态和权限语义，避免重复定义或只改一层。

## 5. 后续确认问题

- 迁移获批后，需要由项目负责人确认 `sys_user_store_scope` 的授权维护入口、授权撤销的历史审计保留时长和已有用户回填策略。
- 需要确认费用确认被拒绝或需要补充材料时，是否新增显式的 `REJECTED`/`NEEDS_INFO` 状态，还是继续由异常/审计记录承载。
- 需要确认 `LABEL_READY` 后续是否只允许下载面单，还是还需要独立的面单文件附件和权限模型。
