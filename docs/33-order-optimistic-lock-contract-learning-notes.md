# 订单乐观锁契约学习笔记

## 业务流程

- 订单从报价创建后处于 `DRAFT`，初始 `version` 为 0。
- 订单详情、订单列表、创建订单及订单写操作响应都返回当前 `version`。
- 草稿更新、提交和取消必须携带调用方最后一次读取到的 `version`。
- 写操作成功时数据库原子递增 `version`，响应返回递增后的值，前端立即替换内存中的旧版本。

## 参与方与规则

- 租户用户只能操作 JWT `tenant_id` 范围内的订单。
- 草稿更新只允许修改地址、商品明细和备注；计价与报价快照字段仍禁止修改。
- 草稿更新先以 `tenant_id + order_id + DRAFT + version` 原子占用版本，再在同一事务中更新订单聚合。
- 提交只允许 `DRAFT -> PENDING_INBOUND`；取消只允许 `DRAFT/PENDING_INBOUND -> CANCELLED`。

## 异常路径

- 版本不匹配时更新行数为 0，返回 `COMMON-1005`（HTTP 409），不继续修改地址、商品或审计记录。
- 状态不允许时返回 `ORDER-1001`（HTTP 409）。
- 草稿聚合后续写入失败时事务回滚，已递增的版本也随事务回滚。

## 验证重点

- 单元测试验证旧版本在明细变更前被拒绝，以及成功写入返回新版本。
- MockMvc 验证创建、详情、列表和草稿更新 JSON 都包含 `version`。
- 本轮不执行 MySQL 集成测试、真实 HTTP 或浏览器测试。
